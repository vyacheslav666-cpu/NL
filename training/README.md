# Обучение сетей для «Узнать символ»

Три MLP (вход N×N → 256 ReLU → 36) для N = 8, 10, 16. Классы — цифры 0–9 и
латинские буквы A–Z, строчные слиты с заглавными (l входит в L, g — в G).
Веса зашиты в страницу одной base64-строкой (`NETS_B64`): gzip от float16
подряд, по сети — `W1[256×N²]`, `b1[256]`, `W2[36×256]`, `b2[36]`, порядок
сетей 8, 10, 16.

## Данные

- **MNIST** — цифры, 60 000 обучающих.
- **EMNIST ByClass** — цифры и буквы, 62 класса, 671 585 обучающих. Берётся
  из выгрузки TensorFlow Federated (`fed_emnist.tar.bz2`): сайт NIST из
  контейнера недоступен. Картинки там уже правильно ориентированы и
  инвертированы (фон = 1), `data.load_emnist` переворачивает яркость и
  сводит 62 класса к 36.

Цифр в данных в 30–70 раз больше, чем редких букв (K — 4 940, цифр — 400 тыс.),
поэтому за эпоху берётся поровну каждого класса: по 5 000.

### Шум в EMNIST

По фону EMNIST рассыпаны слабые пиксели яркостью 1–10 из 255. `to_grid`
строит рамку по любому ненулевому пикселю, и с шумом буква в обучении
занимала 60–70% кадра вместо 82%, как на странице. Сеть, обученная на таком,
давала 87% на тесте EMNIST, но печатные буквы, нарисованные на странице,
путала с цифрами: H, N, W читались как 4, U как 0, D как 0. Мелкий символ в
рамке был для неё признаком буквы, крупный — цифры. `load_emnist` обнуляет
всё до 10 из 255; это 1.4% суммы чернил, почти весь — шум.

## Результат

Точность — среднее по 36 классам на 87 483 тестовых (EMNIST + MNIST):

| | 8×8 | 10×10 | 16×16 |
|---|---|---|---|
| среднее по классам | 84.3 | 85.8 | 86.8 |
| только цифры MNIST | 86.3 | 91.4 | 91.4 |

На MNIST сеть почти не ошибается между цифрами — ответ среди одних цифр верен
в 99% случаев. Ошибки — это цифры, ушедшие в похожую букву: 1→L, 2→Z, 5→S,
4→Y, 6→G/B, 0→O. Хуже всего узнаются O, I, L, Q, G: без контекста их не
отличить от 0, 1, 9. Сдвиг в пользу цифр на выходе пробовали — цифры MNIST
прибавляют 0.1 п.п., буквы теряют 3–6, не взят.

Векторные начертания (`styles.py`): 93 верных голоса из 105. Все 21 печатная
буква на 16×16 и 10×10 верны. Не читаются: девятка с длинным хвостом-крючком
(это и есть строчная g), шестёрка (строчная b), единица с засечкой (7).

## Запуск

```
python train36.py 40 256 8,10,16   # обучение, ~50 мин на 4 ядрах -> nets36.npz
python pack.py                     # -> nets_b64.txt + stats.json
python update_html.py              # подставляет их в ../index.html
python -c "import numpy as np, styles; styles.report(np.load('nets36.npz'), '')"
```

Данные кладутся рядом: четыре `.gz` MNIST с
`https://storage.googleapis.com/cvdf-datasets/mnist/` и
`https://storage.googleapis.com/tff-datasets-public/fed_emnist.tar.bz2`
(распаковать, нужны `fed_emnist_train.h5` и `fed_emnist_test.h5`; читаются
через `h5py`).

`train.py` и `train2.py` — прежняя версия, только цифры (10 классов, 64
нейрона); `pack.py` их выход больше не принимает. Почему тогда переобучали
цифры — девятка с загнутым хвостом читалась как 3 — см. историю коммитов.
